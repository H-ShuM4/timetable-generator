# 大学時間割自動生成システム 設計仕様書

この文書は、システムが**なぜ**この形をしているかを説明する。何を作るかを実装順に並べたものは `docs/superpowers/plans/2026-08-10-timetable-generator.md` にある。制約 ID・データモデル・入力 Excel の列構成は、この文書が正である。

## 1. 目的と背景

大学（経営学科・会計学科）および短期大学部の時間割を、既存の Excel 資産と生成 AI（Google Gemini）を用いて半自動で作成する。事務局が手作業で行っている曜日・時限の割り当てを支援し、制約違反の見落としを防ぐことを目的とする。

技術的な要点は一つに尽きる。**時間割生成という制約充足問題を LLM 単体で解こうとせず、小さなチャンクへ分割して LLM に配置させ、決定的な検証器で囲い込む。** LLM は候補を出す装置であって、正しさの保証はしない。保証は検証器とソルバーが受け持つ。

## 2. スコープ

### 対象

- 経営学科・会計学科・短期大学部の 3 課程
- 曜日：月〜金、時限：1〜5 限
- 開講期：前期・後期（短期大学部の一部はクオーター制：前①・前②・後①・後②）
- 曜日・時限の割り当てのみ

### 対象外

- 教室（講義室・PC 教室）の割り当て。ただし将来追加できるよう、制約層をデータ構造から分離して設計する
- 学生個人の履修登録・時間割
- 「集中」講義（時限 99）の配置。読み込みはするが、時間割グリッドからは除外し、別枠の一覧としてのみ保持する

## 3. 技術スタック

| 層 | 採用技術 | 理由 |
|---|---|---|
| フロントエンド | HTML / CSS / JavaScript（フレームワークなし） | 事務局 PC で追加インストールなく動く。ログの SSE 受信も標準 API で足りる |
| バックエンド | Python 3.14 + FastAPI | ログのリアルタイム配信（SSE）と非同期処理が標準。型定義がそのまま API 仕様になる |
| Excel 読み書き | openpyxl | 既存 Excel が整形済みのため、列を直接構造化して読む方が型が保証され検証も確実 |
| Excel フォールバック | MarkItDown | 想定外の列構成の Excel が投入されたときの経路として併用 |
| 生成 AI | Google Gemini（`google-genai`） | モデル名は設定画面から変更可能 |
| 永続化 | サーバ上の JSON ファイルと Excel の実体 | DB を立てずに済み、中身を目視してデバッグできる |
| テスト | pytest | Gemini はモックに差し替え、API キーなしで全テストが通る |
| ブラウザ検証 | Playwright | fetch の往復・SSE・ドラッグ&ドロップ・ダウンロードは実ブラウザでしか確かめられない |

配布先の事務局 PC は Windows で、Python 3.11 以降があれば `setup.bat` だけで動く。Playwright は開発機にしか要らないため `backend/requirements-dev.txt` に分けてある。

### 4.4 既知のデータ課題

| 課題 | 対応 |
|---|---|
| 氏名の空白が全角・半角で揺れる | 正規化して突合 |
| 異体字の揺れ（教員一覧 `降籏 光太郎` / カリキュラム `降旗 光太郎`） | `config/name_variants.json` の異体字マッピングで吸収。それでも一致しない場合のみ警告 |
| 非常勤 59 名中 15 名の出勤可能日が空欄 | 担当科目がある場合のみ画面で入力を促す。担当科目がなければ無視 |
| 合同=○ でも単独のままの科目がある（その教員のコマが片方の学科にしかないゼミなど 14 件） | 正常として扱い、警告は出さない。合同=○ は科目が合同開講であることを示し、ペアは教員単位で成立する |
| 同じ科目・教員・開講期の科目が他学科にあるのに片方だけ合同フラグが付いている | 付け忘れの可能性が高いため `joint_flag_mismatch` として警告する |
| 両学科とも合同フラグが未設定の組が 33 件ある | `joint_flag_mismatch` は片方だけ付いている場合しか検出できないため、この 33 件は警告されない。未配置科目 9 件のうち 6 件はこれに起因する。Excel 側で補うべきもので、システムでは検出しない |
| ▲科目は同一授業コードで 2 行 | 1 科目に集約し「必要コマ数 2」として扱う |

## 5. データモデル

### 5.1 Subject（科目）

| フィールド | 型 | 説明 |
|---|---|---|
| `code` | str | 授業コード |
| `name` | str | 科目名称（原文） |
| `base_name` | str | `:会` と `【再】` と先頭 `▲` を除いた正規化名。合同ペアリング・前後期対応・編成規則の突合に使う |
| `class_group` | str（導出） | `base_name` からクラス記号（`【A】` `（A）` のような括弧＋英字 1 文字）も除いた名前。**「同一科目」を問う判定が見る**（H2・H3 の学生衝突と、合同ペアリング） |
| `is_retake` | bool（導出） | 名前に `【再】` を含むか。再履修クラスの印 |
| `department` | Enum | 経営 / 会計 / 短期大学部 |
| `year` | int | 年次配当 |
| `term` | Enum | 前期 / 後期 / 通年 |
| `quarter` | Enum \| None | 前① / 前② / 後① / 後② |
| `category` | Enum | 必修 / 選択必修 / 選択 |
| `courses` | list[str] | コース・フィールド（複数可） |
| `teacher` | str | 教員氏名（正規化済み） |
| `is_remote` | bool | 遠隔フラグ |
| `joint_id` | str \| None | 合同グループ ID |
| `pair_id` | str \| None | 前期・後期の対応グループ ID |
| `slots_required` | int | 必要コマ数。▲科目は 2、通常は 1 |
| `requires_consecutive` | bool | 2 コマ連続が必要か |
| `fixed_slot` | TimeSlot \| None | Excel または編成規則で定まった確定枠 |
| `is_intensive` | bool | 集中講義（時限 99）。グリッド対象外 |

### 5.2 Teacher（教員）

| フィールド | 型 | 説明 |
|---|---|---|
| `name` | str | 正規化済み氏名 |
| `kind` | Enum | 専任 / 特任 / 非常勤 / 不明 |
| `research_day` | str \| None | 研究日（専任のみ） |
| `available_days` | set[str] | 出勤可能曜日（特任） |
| `available_slots` | set[TimeSlot] | 出勤可能コマ（非常勤） |

`kind` が `不明`（教員一覧に存在しない）の場合は、警告を出した上で配置する。生成は止めない。

ここでいう「制約なし」は **H5（出勤可能日）と H6（研究日）に限った例外**であり、H1（同一教員の二重予約）と H7（連続コマ）は名簿の有無に関係なく適用する。名簿に載っていない教員も同時刻に二箇所へは行けない。判定は `Subject.teacher` の文字列一致で行う。

### 5.3 TimeSlot / Assignment / Timetable

- `TimeSlot`: `day`（月〜金）, `period`（1〜5）
- `Assignment`: `subject_code`, `slots`（TimeSlot のリスト）, `source`
- `Timetable`: Assignment の集合。学科 × 学期でビューを切り出せる

`source` は `prelock` / `gemini` / `solver` / `manual` / `inherited` の 5 値で、画面での色分けに使う。**Stage 5.5 の修復は配置を動かしても `source` を変えない。** 修復は置き場所を見直すだけで、そのコマを決めた主体が変わるわけではない。ソルバー扱いに書き換えると、事前ロックした非常勤の枠が別の色で現れる。

### 5.4 開講期間の重なり判定

すべての制約は「開講期間が実際に重なる場合のみ衝突」と判定する。この判定は 1 箇所に実装し、全制約から共有する。

判定の土台は `active_quarters(term, quarter)`、つまり「その科目が実際に走っているクオーターの集合」である。2 つの期間が重なるかは、この集合が交わるかで決まる。集合そのものを必要とする制約もある（H7 を参照）。

| A \ B | 前期 | 前① | 前② | 後期 | 後① | 後② | 通年 |
|---|---|---|---|---|---|---|---|
| 前期 | 重なる | 重なる | 重なる | – | – | – | 重なる |
| 前① | 重なる | 重なる | **重ならない** | – | – | – | 重なる |
| 前② | 重なる | **重ならない** | 重なる | – | – | – | 重なる |
| 後期 | – | – | – | 重なる | 重なる | 重なる | 重なる |
| 後① | – | – | – | 重なる | 重なる | **重ならない** | 重なる |
| 後② | – | – | – | 重なる | **重ならない** | 重なる | 重なる |
| 通年 | 重なる | 重なる | 重なる | 重なる | 重なる | 重なる | 重なる |

前期と後期は常に重ならない。通年は年間を通じて開講されるため、どの期間とも重なる。

実データで開講期間が `通年` なのは短期大学部の `J19901 模擬ブライダルプロジェクト` 1 件のみで、これは集中講義のためグリッド対象外である。それでも判定を正しく実装するのは、この科目が通常開講に変わったときに制約が黙って素通りするのを防ぐためである。

### 5.5 同一コマの結び付き

2 種類の結び付きがあり、どちらも「同一コマ」を要求する。

- `joint_id`（H4）：経営側と会計側に分かれた 1 つの合同授業
- `pair_id`（H12）：同じ教員が前期と後期に続けて持つ対応科目

**両方を持つ科目があるため、結び付きは推移的にたどる。** 日本語リテラシーⅡ【再】（経営）は会計側と合同であり、かつ前期のⅠ【再】と対応するので、1 つのまとまりは 4 科目になる。`constraints/linking.py` の `linked_group` がこのまとまりを返し、**ソルバーも手動移動も同じ定義を使う。** 片方だけが結び付きを知っている状態にすると、ソルバーが後で詰む配置を選ぶ。

## 6. 制約

すべてハード制約とする。ソフト制約は設けない。配置の「好み」は制約ではなく別の仕組みで扱う（§7 の Stage 5・5.5）。

| ID | 制約 | 判定単位 |
|---|---|---|
| H1 | 同一教員が同曜日・同時限に別科目を持たない | 全学科横断。**同じ `joint_id` を持つ科目同士は除外** |
| H2 | 必修同士が衝突しない | 学科 × 年次。**同一科目名の複数クラスは対象外** |
| H3 | 選択必修同士が衝突しない | 学科 × 年次 × コース。異なるコース間は衝突可 |
| H4 | 合同科目のペアは同曜日・同時限 | 合同グループ単位 |
| H5 | 非常勤は出勤可能な曜日・時限のみ／特任は出勤可能な曜日のみ | 教員単位 |
| H6 | 専任の研究日には配置しない | 教員単位 |
| H7 | 同一教員が同一日に 4 コマ以上連続しない | 教員 × 曜日 × **クオーター区間** |
| H8 | 遠隔=○ は金曜のみ、遠隔=× は金曜以外、空欄は制限なし（全学科共通） | 科目単位 |
| H9 | 曜日・時限が確定している科目は不動 | 科目単位 |
| H10 | ▲科目（`requires_consecutive=true`）は同一日の連続 2 コマに配置 | 科目単位 |
| H12 | 前期・後期の対応科目は同曜日・同時限 | 対応グループ単位。`config/paired_subjects.json` で定義 |
| H13 | 朝学習の時間には授業を置かない | 学科 × 年次 × 曜日。`config/department_rules.json` で定義 |

**H11 は欠番である。** 「同一教員が同一日に 5 コマ以上持たない」という規則は不要である。時限は 1〜5 の 5 コマしかなく、5 コマ持つには全部を取るしかないため、5 コマ連続となって H7 が必ず先に弾く。走査を二重に行うぶん生成が遅くなるだけである。**番号は再利用しない。**

### 学科ごとの編成規則

事務局が定めた運用で、Excel には現れないものを `config/department_rules.json` に置く。学年や学科が増えたときにコードを触らずに足せる。ファイルが無い・壊れている場合は規則なしとして扱う。時間割が作れなくなるより、規則が効かないほうが害が小さい。

**朝学習（H13）**：会計学科 1 年は月・火・木・金の 1 限が朝学習にあてられており、授業を置かない。他の学科・学年は対象外。**`【再】` にも掛けない。** 朝学習は 1 年生の運用であり、再履修クラスを受けるのは 2 年生以降だからである。実データでは 会計 1 年の `【再】` 13 件がこの規則で月火木金の 1 限から締め出されていた。

**水曜の編成**：会計学科 1 年の水曜は 1 限から 4 限まで事務局が科目を決めている（1 限 商業簿記Ⅰ・Ⅱ、2 限 商業簿記演習Ⅰ・Ⅱ、3 限 工業簿記Ⅰ・Ⅱ、4 限 工業簿記演習Ⅰ・Ⅱ）。読み込み時に Excel の曜日時限指定と同じ `fixed_slot` として与えるので、Stage 1 の確定配置と H9 がそのまま効き、画面では動かせない。対応は `base_name` で取るため【再】クラスも自動的に含まれ、1 科目名につき通常と【再】の 2 クラスが同じコマに入る。経営 1 年や短大 1 年にも同名の科目があるが、学科と年次で絞るので巻き込まない。

**水曜の枠は `【再】` を含めたままにする。** 朝学習と違い、これは事務局が科目名で明示指定した枠である。突合は `base_name` で取るので通常クラスと `【再】` クラスが同じコマに入る。同じ授業を同じコマで開くという現行の運用をそのまま写したものなので変えない。

**連続コマ数の除外**：この 4 コマは担当教員が必ず 4 連続する。H7 で数えるときこの枠を数に入れない。除外は**この枠だけ**で、同じ教員の他の授業は通常どおり数える。「無視してよい」を教員まるごとに広げると、関係のない授業まで規則の外に出てしまう。

**出勤可能コマは朝学習に優先する**：非常勤の出勤可能コマ（H5）と朝学習（H13）がぶつかったときは H13 が譲る。朝学習は時間帯の運用だが、その先生が来られるかどうかは動かしようがない。実データでは リサーチ入門:会 の担当が金 1 限しか出勤できず、その金 1 が朝学習にあたる。条件は科目の列挙ではなく「**出勤可能コマがすべて朝学習に重なるなら譲る**」と書く。事務局が教員一覧を更新するたびに同じ組み合わせが新しく生まれうるためである。該当した科目は `morning_study_exception` として警告に出し、事務局が例外の発生に気づけるようにする。

### 各制約の補足

**合同は学科をまたぐとは限らない。** 経営情報活用（A）と経営情報活用【再】はどちらも経営 2 年前期・築雅之で、事務局は両方に合同フラグを立てている。通常クラスと再履修クラスを一緒に開くという意味である。ペアの成立条件は「同じ `class_group`・教員・開講期の科目のうち、フラグの立ったものが 2 つ以上」とし、**学科をまたぐことは条件にしない**。実データではこの緩和で 1 組だけ増え（109 → 110 組）、どの組も 2 件のままである。

**H1 の除外対象（合同ペア）**：合同科目のペアは 2 行に分かれているが物理的には 1 つの授業であり、担当教員も同一である（実データの合同 107 グループすべてが該当）。H4 が同一コマへの配置を要求する以上、H1 が同一教員として衝突を報告してはならない。両者は直接矛盾するため、H1 は `joint_id` が一致する相手を無視する。

**H2 の除外対象（同一科目の複数クラス）**：`class_group` が一致する必修科目同士は衝突とみなさない。担当教員ごとにクラスが分かれていても学生はそのうち一つを履修するため、同一コマに集約してよい。事務局も従来この方法で過密を解消してきた。**同じ除外を H3（選択必修）にも掛ける。** 必修だけ除外して選択必修は除外しない理由が無い。

**`class_group` は `base_name` とは粒度が違う。** 英語Ⅰ【A】〜【E】や 経営情報活用（A）は 1 科目を教員ごと・開講期ごとに割ったクラスなので、「同一科目か」を問う判定はすべて `class_group` を見る。学生の衝突判定（H2・H3）と合同ペアリングがこれにあたる。一方 `base_name` は**設定ファイルが科目名で突合するため**に要る（前後期対応の `paired_subjects.json`、水曜の編成規則の `department_rules.json`）ので、定義は変えない。

クラス記号は**角括弧と丸括弧の両方**が使われている（`【A】` と `（A）`）。`【留学生】` `（日本国憲法を含む）` `（Photoshop）` のような英字 1 文字でない括弧は外さない。科目名の一部であって、クラス分けではない。

**H2・H3 の除外対象（再履修クラス）**：`【再】` は 1 年次に落単した学生が履修するクラスで、配当年次は 1 年でも実際に受けるのは 2 年生以降である。**その年次の集団に属さない**ので、同じ年次の他の必修・選択必修とは衝突しない。ただし **`【再】` 同士は従来どおり衝突する。** 2 科目を同時に再履修する学生がいるため、重ねると片方を落とすことになる。判定は `_same_cohort` に「`is_retake` が一致すること」を足して表す。

この 2 つの除外の効きは大きい。実データで同一学科×年次かつ開講期間が重なる必修ペアは 1347 組あったが、クラス記号違い 31 組と片方だけ `【再】` の 273 組を外して **1043 組**になる。無用な制約はソルバーの自由度を奪い、前年度を踏襲できる件数も減らしていた。

対象はゼミ科目に限らない。日本語リテラシーⅠ（9 クラス）や課題研究Ⅰ（18 クラス）のようなゼミ系だけでなく、英語Ⅰ・情報リテラシーⅠ・商業簿記Ⅰ のように複数クラス開講される通常科目も同じ扱いになる。`base_name` は `:会`・`【再】`・先頭 `▲` を除いた名前なので、`日本語リテラシーⅠ` と `日本語リテラシーⅠ【再】` も同一科目とみなされる。

この規則は必修の必要コマ数を大きく下げる。実データでは 経営 1 年前期 26 科目→18 コマ、会計 1 年前期 24 科目→15 コマ、短期大学部 1 年前期 29 科目→15 コマとなり、いずれも 25 コマに収まる。

**ゼミという区分は制約判定に持たない。** 上の一般化により、ゼミだけを特別扱いする理由が無くなった。ゼミを参照する機能が現れたら、そのときに区分を入れる。

**H7 はクオーター区間ごとに判定する**：H7 は 3 科目以上をまとめて見る唯一の制約である。他の制約は 2 科目の重なりを見るだけなので `periods_overlap` で足りるが、H7 で「対象科目と重なる科目」を一括りにすると、互いには重ならない後①と後②の科目まで一緒に数えてしまう。

たとえば 水1（学期全体）・水2（後①）・水3（後②）という配置は 3 コマ連続に見えるが、後期前半は水1・水2、後期後半は水1・水3 であって、3 コマ連続する瞬間は存在しない。判定は `active_quarters` が返すクオーター区間ごとに行う。

**H7 の連続上限は 3 とする（`MAX_CONSECUTIVE`）。** この値は「ゼミの隣接をどれだけ実現できるか」で決まる。課題研究（3 年）と卒業研究（4 年）を隣り合わせるとその教員はその曜日に 2 コマ連続し、前後にもう 1 コマ持てば 3 コマ連続になる。実データで上限 2 のとき隣接が成立するのは 63 組中 23 組にとどまり、3 にすると 55 組へ跳ね上がる。未配置も 15 件から 6 件へ減る。

1 人の教員にコマが積み上がる心配は要らない。時限は 5 コマしかないので、1 日 5 コマ持つには全部を取るしかなく、それは 5 コマ連続となって H7 自身に触れる。**連続 3 コマまでという上限が、1 日 4 コマまでという上限を含んでいる。**

**H10 の例外**：`▲プレゼミナール` のみ `requires_consecutive=false`（現行データが火 2 / 木 2 の別日配置のため）。この例外は `config/subject_overrides.json` で管理し、ハードコードしない。

**H7 と H10 の関係**：▲科目の 2 コマ連続は H7 に違反しない（連続 2 コマは上限の内側）。

**H8 は全学科に同じ規則を適用する。** 大学（経営・会計）の金曜は全科目が遠隔授業なので、遠隔で行えない科目（×）は金曜に置けない。一方、短期大学部の金曜は遠隔と対面が混在するため、○ 以外は金曜に置いてよい。

この差は**学科で分岐して表現しない。** 遠隔列の ○ / × / 空欄をそのまま 3 状態として読めば足りる。大学シートには空欄が無く、短大シートには × が無いため、1 つの規則で両方の運用を満たせる。○ か否かの 1 ビットしか読まないと × と空欄が同じ値になり、「対面科目を金曜に置かない」を全体スイッチで表すしかなくなる。そのスイッチは短大の空欄 149 科目まで金曜から締め出すため実用にならない。

実データでの配置可能性は検証済みである。遠隔=○ は 89 科目（経営 44・会計 32・短大 13）あるが、金曜 5 コマに対して、同一コホートで別コマを要する必修は最大 4 種、1 人の教員が同一学期に持つ遠隔科目も最大 4 コマ、遠隔科目の担当教員に金曜出勤できない者はいない。実測でも 89 科目すべてが金曜に配置され、制約違反は 0 である（大学の金曜配置は ○ ちょうどの 76 コマ、短大は 35 コマ）。

### 制約層の設計原則

制約の検証は `constraints/validator.py` に集約し、以下がすべて同じ検証器を呼ぶ。

1. Stage 1 の事前ロック
2. Gemini の応答検証
3. ソルバーの探索中の枝刈り
4. Stage 5.5 の修復
5. 画面からのドラッグ&ドロップ編集

これにより「AI 経由なら通るのに手動編集では弾かれる」といった不整合が原理的に発生しない。教室制約を将来追加する場合も、このモジュールにルールを 1 つ追加するだけで全経路に反映される。

**検証を経ずに `Timetable.place` を呼ぶ経路を作らない。** 例外は「曜日時限が既に確定している枠の書き込み」だけで、それは選択の余地が無いためである。

## 7. 生成パイプライン

### Stage 0 — 読み込みと検証

Excel を構造化し、以下を警告一覧として作成する。**警告があっても処理は止めない。**

- 教員一覧に存在しない担当教員
- 担当科目があるのに出勤可能日が空欄の非常勤
- 合同=○ だがペアが成立しない科目
- コース列が空の選択必修科目
- 曜日・時限が片方だけ入力されている科目

**Excel からセッションの中身を組み立てる手順は 1 本しかない。** `ingest/session_builder.load_session_data` が唯一の入口で、アップロードも復元もここを通る。科目同士の結び付け（合同と前後期）も `ingest/pair_linking.link_subjects` に 1 つだけ置き、パイプラインもテストのフィクスチャもここを通る。前処理が増えるたびに全呼び出し箇所を思い出さなければならない構造にすると、いつか必ず取りこぼす。

### Stage 1 — 事前ロック（Python のみ、AI に渡さない）

1. `fixed_slot` を持つ科目（H9）をそのまま配置
2. **非常勤**教員の担当科目を、出勤可能コマに決定的に配置する。候補コマ数が少ない教員から順に処理し、H1・H7 を確認しながら確定させる

**特任教員は事前ロックの対象外とする。** 特任の制約は曜日単位（H5）にとどまり時限が定まらないため、Python が機械的に選ぶと恣意的な配置になる。特任の科目は Stage 2〜4 で通常どおり扱い、H5 の曜日制約を適用する。

この段階の結果は以降のステージで**占有済みマップ**として扱われ、Gemini には「そのコマが埋まっている」という事実のみが渡る。トークン削減と、確定枠が AI に動かされないことの保証を兼ねる。

置けなかった非常勤科目は警告に回す。多くは実在の制約衝突であって不具合ではないので、生成は続ける。

### Stage 2〜4 — Gemini によるチャンク配置

必修 → 選択必修 → 選択 の順に処理し、各段階をさらにチャンクへ分割してリクエストする。

**チャンクのキーは 学科 × 年次 とする。**

- **年次を含める**理由：学生側の衝突規則 H2（必修同士）と H3（選択必修同士）がどちらも「学科 × 年次」で判定される。年次で切ると各チャンクが「互いに衝突しうる科目だけの塊」になり、Gemini が考慮すべき範囲とチャンクの範囲が一致する
- **コースは含めない**理由：H2・H3 はコースを見ない。細分しても衝突の判定範囲は変わらず、リクエスト回数だけが増える
- **開講期も含めない**理由：H12 は前期と後期の対応科目に同一コマを要求するが、制約は置いたあとにしか効かない。学期で切ると対応する 2 科目が必ず別のリクエストになり、前期を先に置いた時点で後期の行き先が 1 コマに固定される。そこが後期の別の必修で埋まっていれば後期は置けない。実データの前後期ペア 95 組は、学期で切ると 95 組とも別チャンクに分かれる。同じチャンクに入れれば Gemini が両方の候補を見比べて共通のコマを選べる

**占有情報はチャンクの担当教員だけに絞る。** 全教員ぶんの「既に埋まっているコマ」を載せると、時間割が埋まった状態でプロンプトの 76% をそれが占める（3,969 字中 3,029 字、教員 82 名ぶん）。1 リクエストで扱う科目の担当は数名で、残りは判断に関係しない。候補コマの一覧が既に全制約を通した結果なので、占有情報は担当教員の状況を補足するためだけにある。絞れば同じ場面で 1,195 字に収まる。

**リクエスト回数が Gemini の無料枠を左右する。** 無料枠は 1 モデルあたり 1 日 20 リクエストで、1 回の生成には最良でもチャンク数と同じだけかかる。キーの選び方による差は大きい（配置対象 576 科目での実測）。

| キー | Stage 2 必修 | Stage 3 選択必修 | Stage 4 選択 | 合計 | 最大プロンプト |
|---|---|---|---|---|---|
| 学科 × 年次 × 開講期 × コース | 28 | 22 | 20 | **70** | — |
| 学科 × 年次 × 開講期 | 20 | 10 | 16 | **46** | 3,385 字 |
| **学科 × 年次**（採用） | 10 | 5 | 8 | **23** | 5,387 字 |

再試行を含めた最悪ケースは 23 × 再試行回数（既定 3）＝ 69 リクエスト。予備モデルを 5 つ選べば 100 リクエストの予算になり収まる。

各チャンクのループ：

```
プロンプト（対象科目 + 占有済みマップ + 適用制約）
  → Gemini が JSON で配置案を返す
  → validator が検証
  → 違反ゼロなら確定
  → 違反があれば「どの科目がどの制約に違反したか」だけを添えて差し戻す
  → 設定した再試行回数まで繰り返す
```

差し戻し時は**違反した科目のみ**を再配置対象とし、成功済みの配置は再送しない。再試行のトークンが線形に膨らむのを防ぐ。応答は JSON スキーマを指定して受け取り、パース失敗も再試行の対象とする。

例外はチャンク単位で捕まえる。1 チャンクの失敗で生成全体を落とさない。

### Stage 5 手前 — 分かれた組を置き直す

H4（合同）と H12（前後期）は同一コマを要求するが、**制約は置いたあとにしか効かない**。片方が先に置かれると残りはそのコマ以外を選べず、そこが埋まっていれば永久に置けない。ソルバーは自分でグループごと置くとき先読みしてこれを避けるが、**Gemini が片方だけ置いて残りを未確定にした場合は手遅れになる。**

この状況は AI モードでしか生じない。ソルバーだけで組む場合は先読みが常に効くためである。実データの AI モードで 2 件現れる（合同の経営側が金 1 に入ったが会計側は朝学習で金 1 に置けない／日本語リテラシーⅠ・Ⅱ【再】の 4 科目のうち 3 件が月 2 に入り、残る 1 件が後期の月 2 の必修とぶつかる）。

そこでソルバーへ渡す前に、一部だけ置かれたグループの**置かれているほうを外す**。ソルバーは全員が入れるコマだけを候補にするので、同じ行き違いが起きない。事務局が曜日時限を決めた枠を含むグループは外さない。

### Stage 5 — ソルバーによるフォールバック

再試行を使い切っても未確定の科目を、Python の貪欲探索で埋める。毎回「配置可能なコマ数が最も少ない科目」を選んで確定させる（最小残余値ヒューリスティック）。候補が 1 つも無い科目はその場で未配置として記録し、残りの処理を続ける。

これが「必ず完成する」保証となる。**未配置は例外ではなく結果である。** 画面に科目名と担当教員を出し、事務局が手で置けるようにする。

**バックトラッキングは採用しない。** 1 ノードあたり 0.21 秒（残り全科目の候補再計算）かかり、443 科目規模では探索が現実的な時間で終わらない。最小残余値ヒューリスティックによる貪欲配置は 90 秒で 443 科目中 435 科目を配置し、制約違反 0 を達成する。未配置の 8 科目は候補が 1 つも無いもので、バックトラッキングでも配置できない。

配置済みの科目を動かせば解が見つかる可能性は残るが、それは Gemini の再試行と事務局の手動編集が担う。ソルバーの役割は「必ず終わり、必ず制約を満たす結果を返す」ことである。

**候補の再計算は影響範囲だけに絞る。** 1 件確定させるたびに残り全科目の候補を作り直すと、実データでは 611 件を置くのに候補列挙 62,519 回・制約検査 1,648,920 回、所要 33.6 秒になる。

科目を 1 つ置いて候補が変わりうるのは、**担当教員を共有する科目**（H1・H7、および合同の H4 と前後期の H12。どちらも同一教員でしか成立しないためここに含まれる）と、**学科と年次を共有する科目**（H2・H3）だけである。残る H5・H6・H8・H9・H10 は他の科目を見ないので、何を置いても判定は変わらない。この 2 つに絞ると 12,958 回・346,645 回・7.2 秒になり、**結果は 1 件も変わらない**（配置 611・未配置 2・違反 0、前後期ペア 95/95、ゼミ隣接 50/63）。

構造だけで決まる候補（`candidate_slot_sets`）は配置状況に依らないので、探索の最初に一度作って使い回す。

影響範囲の見積もりが狭すぎると古い候補で制約違反を作る。`tests/test_solver_incremental.py` が「1 件置いて候補が変わった科目が見積もりに収まること」を実データで検証する。教員か学科×年次のどちらを落としてもこのテストは失敗する。

**同一コマの結び付きは先読みして置く。** ソルバーは `linked_group`（§5.5）で結び付きを推移的にたどり、まだ置かれていない相手も一緒に置ける候補だけに絞ってから確定させ、相手を同じコマへ即座に置く。相手は別の学期なので、こちらを置いても相手の判定は変わらない（H1・H2・H3 は開講期間が重なる科目しか見ない）。全員が入れるコマが 1 つも無い場合はこの科目だけを置く。誰も置かないより配置数が多くなるためである。

効果は大きい。未配置 6 件が 2 件へ、前期・後期の対応 95 組すべてが同一コマに揃い、生成時間も 54 秒から 33 秒へ縮む（詰む配置を避けるぶん探索の無駄が減る）。代償としてゼミの隣接が 55 組から 50 組へ下がる。ペアを早い段階でまとめて確定させるため、隣接相手がまだ置かれていない場面が増えるからである。**配置数を優先して受け入れる。**

**候補コマの選び方（制約ではなく好み）**：配置可能なコマが複数あるとき、`scheduler/preference.py` の `placement_preference` が次の優先順で最良の候補を選ぶ。

1. **5 限を使う数が少ないこと。** 経営・会計には本システムの対象外である教職課程の科目があり、事務局によればそれらは 4 限・5 限に置かれることが多い。通常科目を 1〜4 限へ寄せておくと教職課程と衝突しにくい。短期大学部も同じ扱いにする（短大の 5 限は元々 3.4% しか使われておらず、除外しても差が出ない）
2. **既に埋まっている科目数が少ないコマであること。** これが無いと候補生成順（月曜が先）に引きずられて木曜がほぼ空になる
3. 同点なら曜日・時限の辞書順（結果を再現可能にするため）

これは**ハード制約ではない。** 5 限しか空いていなければ 5 限に置く。対象学科は `preference.PREFER_EARLY_PERIODS` に列挙してあり、外せばその学科は寄せなくなる。実データでの 5 限使用率は経営 0.8%・会計 0.9%・短大 3.4%。

**好みはソルバーと Gemini プロンプトの両方が同じ場所から読む。** 片方だけが好みを知っていると、モックモードと AI モードで時間割の性格が変わる。

**ゼミの隣接**：課題研究（3 年）と卒業研究（4 年）は、同じゼミ内で 3 年生と 4 年生が交流できるよう可能な限り隣り合う時限に置く。これも制約ではなく好みで、`adjacent_id` と `placement_preference` が担う。ソルバーは候補数が同じ科目のうち、隣接相手が既に置かれているものを先に確定させる。

**前期・後期の対応付け（H12）の作り方**：日本語リテラシーⅠとⅡ、課題研究ⅠとⅡ、卒業研究ⅠとⅡのように、同じ教員が前期と後期に続けて受け持つ科目は同じコマに置く。学生が通年で同じ曜日・時限に出席できるようにするための運用規則である。対応関係は `config/paired_subjects.json` に書き、`assign_pair_ids` が **教員単位**で結ぶ。授業コードの末尾は一致しないことがあり（荒牧裕一の課題研究は Ⅰ が B63120、Ⅱ が B63200）、同じ教員が同じ科目を 2 コマ持つ場合はコード順に 1 対 1 で対応させる。実データでは 95 組・190 科目が成立し、片方の学期しか持たない教員の 8 科目は対応なしのままになる。

### Stage 5.5 — 配置の見直し（修復）

事務局が生成画面のスライダーで重みを決め、置いたあとに「良くなる移動」を探して適用する。**制約を満たす移動しか行わない**ので、配置済みの科目が未配置に戻ることはない。すべて「気にしない」なら何も動かさず、結果は修復を入れる前と同一になる。

**配置そのものは変えない。** ソルバーの好みは辞書順で比べており、ここに重み付けを持ち込むと未配置 0 件を達成している配置が揺らぐ。重みは修復だけに効かせ、置き方から切り離す。

対象は 5 項目（学生の空きコマ／学生の登校日数／教員の空きコマ／1〜4 限への集約／ゼミの隣接）で、各 3 段階（気にしない 0・標準 1・重視 3）。**項目同士は競合する**（登校日数を詰めれば 1 日が長くなって空きコマが増えやすく、逆もまた然り）ので、どちらを取るかは事務局が実際の時間割を見比べて決める。システム側は重み付き合計で順位を付けるだけにする。かける時間も 3 段階（しない／5 秒まで／1 分まで）で選ぶ。値はブラウザに覚えさせる。

**順位付けは影響範囲だけを数える。** 候補コマごとに時間割全体を計測すると 613 科目 × 25 コマ × 全走査になり終わらない。1 つの科目群を動かして値が変わるのは、その科目の学科×年次×クオーター区間、担当教員、隣接相手だけで、他は動かないため比較の際に相殺される。索引を 1 度作り、その範囲だけを数える。

**空きコマと登校日数はクオーター区間ごとに数える。** 学期でまとめると、互いに重ならない前①と前②の科目が同時開講として数えられ、実際には誰も体験しない空きコマを数えてしまう。制約は §5.4 の `active_quarters` で厳密に判定しているのだから、好みの計測も同じ土台に載せる。実データの必修クオーター科目は 25 件ある。

区間ごとの合計は `QUARTERS_PER_TERM`（2）で割って**学期あたりの値**に戻す。学期をまたぐ科目は 2 区間ぶん数えられるため、割らないと区間で数える項目だけが実質 2 倍の重みを持ち、5 限やゼミ隣接との釣り合いが崩れる。実際、割らずに測ると同じスライダー設定で 5 限が 7→9、ゼミ非隣接が 16→20 と悪化した。**索引側と最終計測の両方で割る。** 片方だけだと順位付けと計測が別の尺度になる。クオーター科目が絡むと値は 0.5 刻みになりうる。

合同科目と前後期の対応科目はまとめて動かす。Excel や編成規則で曜日時限が決まっている枠は対象外。**踏襲した枠も対象外とする。** 踏襲モードは前年度と同じコマにロックすると決めてあり、修復がそれを崩すと、事務局が確認しなくてよいはずの科目まで去年と違う場所に現れる。

実データ（5 秒、全項目「標準」＋学生の空きコマ「重視」）：配置 613・未配置 0・違反 0 のまま、学生の空きコマ 20→2、登校日 84.5→76.5、教員の空きコマ 63.5→13.5、5 限 11→7、ゼミ非隣接 19→16。修復そのものは 1.7 秒で収束する。

### Stage 6 — 全体検証と保存

全制約を通しで再検証し、結果と残存違反一覧をセッションのディレクトリへ保存する（§10）。

### モードごとの差分

| モード | 挙動 |
|---|---|
| **モックモード** | Stage 2〜4 をスキップし、Stage 5 のソルバーが全科目を配置。API キー未設定時は自動的にこのモードになる |
| **AI モード** | 上記フルパイプライン |
| **踏襲モード** | Stage 1 の後に前年度時間割を読み込み、組み替え対象外の教員の科目を前年度と同じコマにロックする。組み替え対象のみ Stage 2〜5 に流す。**Stage 2〜4（Gemini）を通すかどうかは画面で選ぶ**（下記） |

**組み替え対象を誰が配置するかは事務局が選ぶ。** 既定はソルバー（`retarget_with: "solver"`）で、AI に任せたいときだけ `ai` を送る。以前は API キーがあるだけで Gemini へ渡していたが、前年度をなぞるのが踏襲モードの目的で、組み替えはその残りにすぎない。数十分と無料枠を黙って使うのは割に合わない。キーが無ければ AI は選べず、画面側でも選択肢を無効にする。AI モードの挙動はこの設定に左右されない。

**踏襲モードの組み替え対象**（自動検出し、画面のチェックボックスで追加・除外できる）：

- 非専任教員（非常勤・特任）の担当科目すべて
- 前年度と今年度で研究日が変わった専任教員の担当科目
- 前年度に存在しない新規科目
- 担当教員が変わった科目

**前年度の 2 本がそろわないと踏襲は 1 件も働かない。** 前年度の時間割が無ければ全科目が「前年度に存在しない新規科目」に落ちる。前年度の**教員一覧**が無い場合も同じで、研究日の比較が「前年度＝なし」対「今年度＝あり」となり全専任が不一致になる。実データではどちらの場合も 613 科目中 613 科目が組み替え対象となり、生成しても普通の生成と同じ結果が返る。4 本そろえて教員が据え置きなら組み替えは 189 件（非常勤 141・特任 48）で、424 件が踏襲される。

**踏襲モードでは事前ロックにも前年度のコマを渡す。** `prelock` は候補集合の先頭を機械的に取る（候補は曜日→時限の順なので月曜 1 限寄りになる）。前年度を見ないと、非常勤の担当科目が前年度と別のコマへ移り、その先に前年度からいた科目を H1・H2・H3 で押し出す。実データでは非常勤 133 件のうち 54 件が動き、11 件を押し出していた。前年度のコマを希望として渡すと 8 件・1 件へ減り、踏襲は 347 件から 365 件へ増える。**候補に残っているものしか選ばない**ので制約は従来どおり全部通り、希望が候補に無ければ先頭を取る。他のモードには渡さない。

非常勤を組み替え対象にしてあるのは出勤可能日が年度で変わるためだが、変わっていないなら前年度と同じコマへ戻すほうが事務局の確認は減る。候補に残っている＝今年度も出勤できて全制約を満たす、ということなので戻して困らない。

**戻せなかった理由は捨てない。** `apply_plan` は `check_placement` で違反を受け取り、制約 ID・メッセージ・ぶつかった相手を `InheritSkip` として返す。ログに 1 件ずつ出し、結果 JSON にも載せて画面の「踏襲できなかった科目」に並べる。「前年度の配置が今年度の制約に合いません」だけでは、原因（前年度の時間割自体の衝突／事前ロックの移動／今年度に入った規則）にたどり着けない。生成のときにしか分からない記録なので、制約違反と違って再計算せずそのまま保存する。実データの分析は `docs/analysis/2026-09-02-inherit-shortfall.md` にある。

**教員一覧が無いときに研究日の比較を飛ばす、という緩和はしない。** 黙って精度が落ちるより、2 本そろうまで画面で選ばせないほうが確かである。エラーも出ずに「動いていないように見える」のが、この機能でいちばん多い躓きだった。

## 8. フロントエンド

### 8.1 画面構成

タブは「① ファイル読込 → ② 生成 → ③ 結果」と「設定」。**番号は実際に順序のある場所にだけ置く。** 読込→生成→結果は順序だが、設定は順序ではない。設定は右端の独立したユーティリティとして分ける。

**① 読込画面**

Excel をドラッグ&ドロップで投入する。ファイル名から役割（今年度カリキュラム／今年度教員／前年度カリキュラム／前年度教員）を推測して割り当て、利用者は必要なら手で直せる。カリキュラムと教員が揃って初めて読み込める。

読み込み後に表示するもの：

- 科目数（学科別・科目区分別）
- 教員数（区分別）
- クオーター科目数
- 集中講義数
- 警告一覧（Stage 0 で検出したもの）

**② 生成画面**

- モード選択（モック / AI / 踏襲）
- **AI モードは API キーが登録されるまで選べない。** キーが無いまま選ぶとサーバは黙ってモックへ落とす（§7 のモード差分）。走り終わってから「AI で作ったつもりだった」と気づくのは遅い。押せない理由と、どこで登録するかをモードの下に出す
- **重み付けは踏襲モードのとき畳む。** スライダー 6 本が先に来ると、その日いちばん触りたい組み替え対象がスクロールの先へ押し出される。モックと AI モードでは開いたままにする
- **踏襲モードは前年度の 2 本がそろうまで選べない。** 欠けているファイル名をモードの下に出す。読み込みサマリも「前年度の時間割」「前年度の教員一覧」を別々に示し、どちらが足りないか分かるようにする
- 踏襲モード選択時は組み替え対象一覧を表示し、チェックボックスで調整。**空リストと未指定を取り違えない。** 「すべて解除」は「何も組み替えない」であって「自動検出に任せる」ではない。API は `retarget_codes` を `null` と `[]` で区別し、画面は踏襲モードのときだけ配列を送る。以前は空リストが falsy として自動検出へ落ち、外したはずの科目 189 件がまとめて組み替え対象へ復活していた。**理由ごとに畳んで件数を見出しに出し**、先頭に「何件を組み替え、何件を据え置くか」を置く。実データでは非常勤だけで 141 件あり、ベタ並びでは規模が読み取れない。まとめて切り替える「すべて選択」「すべて解除」を添える
- 重み付けのスライダー 5 本と、見直しにかける時間（§7 の Stage 5.5）
- 生成開始ボタン、進捗表示、ログビューア

生成が終わったらログを畳んで結果タブへ自動で移る。失敗・切断のときは移らず、理由を出す。API キーが未設定で AI モードを選んだ場合、サーバが実際に走らせたモードを**日本語のラベル**で伝える。

**③ 結果画面**

- 学科タブ × 学期タブでグリッド表示（縦 1〜5 限 × 横 月〜金）。曜日ヘッダーと時限の列は固定する
- **各コマの中は 1 年→2 年→3 年→4 年の順**に並べる。同じ年次の中は科目名、さらに授業コード順。移動後もサーバから取り直して再描画するため順序は保たれる
- ドラッグ&ドロップでコマを移動する。移動先が制約違反になる場合は理由を示して断る
- **結び付いた科目はまとまりで動く**（§5.5）。移動先がまとまりのいずれかで他のハード制約に触れる場合は**まとまり全体を元のコマ・元の `source` へ戻す**（部分適用しない）
- **教員は氏名の一部で絞り込める。** 実データの教員は 82 名で、プルダウンだけでは目当ての先生まで延々スクロールすることになる。入力欄で絞り、何名に絞れたかを添える。氏名は Excel 由来で姓名の間の空白が全角・半角で揺れるため、両方を落として突合する。打鍵ごとに書き直すのは選択肢と件数だけにし、600 枚のカードは Enter かプルダウンの選択まで描き直さない
- **学科別と教員別を切り替えられる。** H1・H5・H6・H7 は教員単位で判定するのに、その教員単位の姿を人が見る手段が無いと違反の理由が追えない。実データでは、担当を持つ教員 82 名のうち 56 名が学科×学期の 3 枚以上にまたがり、最多の 1 名は 21 コマが 5 枚へ散る（学科の数で数えると 3 学科にまたがるのは 25 名）。教員別ではその教員のコマを学科をまたいで集め、担当コマ数・曜日ごとの偏り・区分・研究日・出勤可能コマ数を並べて示す。カードは担当が固定されているので教員名の代わりに学科を出す
- **移動を取り消せる。** まとまりは最大 4 科目が同時に動くため、落とす場所を間違えたときの手戻りが大きい。`move` の応答が「触れた科目とその移動前のコマ」を返し、画面はそれを積んでおく。`Ctrl+Z` と「元に戻す」ボタンのどちらでも戻せる。未配置科目を置いた操作も戻せるよう、配置を外す `POST /api/result/<id>/unplace` を用意する
- 踏襲モードのときは「踏襲できなかった科目」を脇に出す。制約 ID・理由・ぶつかった相手を添える。**朱にはしない**（違反ではないため）
- 未配置科目リスト、集中講義リストをサイドに表示。**未配置科目はドラッグでグリッドへ置ける**（移動 API はまだ置かれていない科目コードも受け付ける）。置く手段が画面に無いと、制約の都合で自動配置できなかった科目に事務局が手出しできない
- 出力（ファイル名を入れて「Excel で出力」を押す。形式は選ばせない）

**④ 設定画面**

- API キーの保存・削除（保存後は先頭数文字のみ表示。全文は返さない）
- モデル選択（プルダウン + 手入力）
- 再試行回数の設定
- **開発者向け：予備モデル**（折りたたみ。既定は選択なし）

### 8.2 画面のデザイン

事務局が毎日触る業務画面である。情報密度・操作性・視認性を落とさずに作る。

**色は意味に結び付ける。** 地は薄い紙色、構造と操作は**藍**、そして**制約違反だけを朱**にする。日本の事務で訂正を書き入れる色が朱であり、朱を違反以外に一切使わないので、画面のどこに朱があっても意味が一つに定まる。手で触ったもの（手動編集・警告）は山吹。

**年次は色相ではなく藍の濃淡 4 段で表す。** 年次は順序のあるデータなので、濃淡のほうが意味に合う。色相を 4 つ足すと画面が騒がしくなる。

**Web フォントを読まない。** 配布先の事務局 PC がオフラインやプロキシ配下だと、読み込み待ちで表示が遅れるか別の書体に化ける。代わりに Windows 10/11 に同梱される **BIZ UDPGothic / BIZ UDGothic** を先頭に置く。UD フォントは公共機関や学校教材向けに可読性を設計したもので、この用途にそのまま合う。無い環境では游ゴシック・メイリオへ落ちる。授業コードや時限の数字は等幅にして桁を揃える。

**期間レール（この画面の要）**：カード左端の 5px の縦線が 2 つの事実を同時に表す。色と塗り分けの 2 つを担うため、細すぎると読み取れない。広げた分は列の間隔から返してもらい（レール +2px に対し間隔 2 つで -2px）、科目名の幅は変えない。

- レールの**色** = 配置元（墨＝事前ロック、深緑＝AI、淡緑＝ソルバー、山吹＝手動、灰＝前年度踏襲）
- レールの**高さ** = 開講期間（全高＝学期全体、上半分＝前①/後①、下半分＝前②/後②）

配置元をカードの**背景色**で示すと、1 コマに 9 科目入るセルがあるため、5 色のパステル背景が並んで密度が上がるほど読みにくくなる。情報をレールへ移せばカードの地が白のまま残り、9 枚並んでも一覧性が落ちない。文字で書いていた `[後①]` も形になる。**装飾ではなく情報を担う要素**である。

レールの色を緑系統にしたのは年次チップが藍系だからで、レールも藍だとチップとの境目が読み取りにくい。レールは形でしか伝わらないため、**同じ内容を `title` に言葉でも持たせる。** 違反時はレールの色そのものを朱に差し替える（子要素なので親に影を敷いても隠れない）。

脇の未配置・集中・違反は件数付きの折りたたみにして、違反が 0 件のときに場所を取らないようにする。文字色は主要な組み合わせで WCAG AA（4.5:1）を満たすこと。

**利用者が入力した文字列や Excel 由来の文字列は、属性値の中も含めて必ずエスケープする。**

### 8.3 セッションの永続化

読み込んだデータと生成結果はメモリ上の辞書に持つが、**それだけでは足りない。** AI モードは数十分と Gemini の無料枠を消費するため、サーバの再起動やブラウザの再読み込みで失われると事務局はアップロードからやり直すことになる。

アップロードされた Excel を `data/sessions/<id>/files/` に保存し、結果は同じディレクトリの `result.json` に書く。**復元時は保存した Excel を同じ読み込み処理に通し直してから結果を重ねる。** 科目や教員を別形式でもう一度持つより、読み込み経路が 1 本のままで済む。制約違反は保存値を使わず `validate_all` で再計算する。保存後に制約を変更した場合、古い判定を見せるほうが害が大きい。Excel が差し替わって消えた科目コードは黙って捨てる。

フロントは ID を `localStorage` に置き、起動時に `GET /api/sessions/<id>` で復元を試みる。失敗すれば保存期間を過ぎたものとみなして忘れる。続けて `GET /api/result/<id>` を見て、**結果があれば結果タブも開けるようにする。** 結果タブを生成完了時のコールバックでしか有効化しないと、復元してもサーバ側にある結果へ辿り着けない。

保持は最新 `MAX_SESSIONS`（10）件で、超えた古い順に削除する。ただし**生成中のセッションは削除しない。** 数十分かかる処理の途中で消えると結果を受け取れなくなる。

### 8.4 ログビューア

画面下部の折りたたみパネル。上下ボタンで表示・非表示を切り替える。バックエンドから SSE でリアルタイムに受信し、同時に `logs/` へ保存する。

記録する内容：

- 各 Stage の開始・終了と所要時間
- チャンク単位の処理内容（対象科目数、学科、開講期）
- Gemini への送信トークン数、応答時間、使用モデル
- 検証で検出した違反の詳細（科目コード、制約 ID、理由）
- 再試行の発生（何回目か、対象科目）
- フォールバックの発動
- 例外のスタックトレース

ログレベルは INFO / WARN / ERROR とし、画面でフィルタできる。

**開いている間は本文の下に余白を足す。** パネルは画面下端に `position: fixed` で重なるため、余白が無いと一番下のボタンがパネルの裏に入って押せなくなる。実際、生成を始めると「中止する」がログに覆われていた。`body` の `padding-bottom` は畳んだときの見出しぶんしか見ていないので、開いている間だけ `body.log-open` でパネルの高さぶんを足す。

**ログは溜めっぱなしにしない。** ファイルを作るのは 1 行でも書いたときだけにし、新しい順に `MAX_LOG_FILES`（10）件を残して古いものを消す。保存しているセッション（`MAX_SESSIONS`）と同じ数にそろえてあり、時間割が残っていない回のログだけが残ることがない。読み込みと復元のロガーは問題が無ければ何も書かないため、この配慮が無いと空ファイルだけが際限なく積み上がる。

**ログ配信は非同期にする。** `StreamingResponse` に同期ジェネレータを渡すと Starlette はワーカースレッド上で回す。`queue.get()` で次のログを待つ実装だと待っている間そのスレッドを占有し、サーバを止めるときこのスレッドは中断できないため `KeyboardInterrupt` と `CancelledError` の長いトレースバックがターミナルに出る。画面を閉じても待ち続けるので購読者も溜まる。

待たずに取り出して無ければ眠る非同期ジェネレータにし、切断時は `unsubscribe` で購読を外す。スレッドを 1 本も使わず、停止にも即座に応じる。無音が続く場合は 15 秒ごとにコメント行を送り、間に挟まる機器に切られないようにする。

### 8.5 静的ファイルのキャッシュ

フロントエンドは `Cache-Control: no-cache` を付けて配信する。付けないとブラウザが Last-Modified から勝手に鮮度を推測し、再検証せずに古い JS を使う。ページ遷移では HTML が再検証されるのに JS・CSS だけ古いまま残るため、「新機能を足したのに画面に出ない」という形で現れる。

`no-cache` は「保存してよいが使う前に必ず確認せよ」の意味で、変更が無ければ ETag により 304 が返るだけなので転送量は増えない。事務局の PC へ更新版を配るたびにキャッシュを手で消してもらうわけにいかないため、サーバ側で解決する。

### 8.6 Gemini のモデル切り替え

**予備モデルによるフェイルオーバー**：無料枠は 1 モデルあたり 1 日 20 リクエストのため、再試行が入ると 1 モデルでは AI モードを完走できない。`fallback_models` に選んだモデルを順に持ち、`RotatingGeminiClient` が枠切れを検出するたびに次のモデルへ移って**同じリクエストを再送**する。枠を使い切ったモデルは以後使わない。

これは開発時に無料枠を足し合わせるための機能である。既定は空で、そのときは 1 モデルだけを使う。事務局の運用でも 1 モデルだけを選ぶ。

**ラウンドロビンではなくフェイルオーバーにする。** 確認したいのは「AI が全科目を割り振った時間割」であってモデルの比較ではない。チャンクごとに品質の違うモデルが混ざると、何の結果なのか読み解けなくなる。第 1 モデルを使い切るまで使い、あふれた分だけ次へ回す。

**503（混雑）も切り替えの理由にする。** 枠切れ（429 / RESOURCE_EXHAUSTED）だけを合図にすると、モデルが混み合って 503 を返したときに同じモデルへ送り直してしまう。混雑は数秒では解けない。実測では 1 回の呼び出しに 2 分 25 秒かかったうえで `503 UNAVAILABLE / high demand` が返ることがある。あわせて 1 回の呼び出しに 90 秒の上限を置き、待ち続けないようにする。

枠切れ・混雑**以外**の失敗ではモデルを切り替えない。それは一時的な失敗であり、既存の再試行で解決しうる。全モデルが枯渇したら `GeminiError` となり、既存の経路でソルバーへ落ちる。

失敗の種別は SDK の例外型ではなく応答中の語で判定する（枠切れ：`RESOURCE_EXHAUSTED` / `quota` / `rate limit`、混雑：`UNAVAILABLE` / `high demand` / `overloaded`）。SDK の例外階層に依存すると、SDK の更新で黙って判定が外れる。

どのチャンクをどのモデルが処理したかはログに残す。**応答を受け取った後に読む**（送信前の名前は切り替えが起きると食い違う）。

## 9. 出力

**Excel だけを出す。** 一時期は画面を印刷して PDF にする道も持っていた（§8.2 の情報設計 — レールの色と塗り分け、年次の藍の濃淡 — を紙に残すため）。しかし事務局の様式に合わせた xlsx が組めるようになり、配布に要る体裁はそちらでそろった。**形を選ばせる必要がなくなったので、経路ごと畳んだ。** 選択肢が 1 つしか無いプルダウン、画面に隠した印刷用の DOM、`@media print` の一式が丸ごと不要になる。PDF が要るときは Excel から印刷すればよい。

### 9.1 Excel

**保存するファイル名は事務局が決める。** 年度や学科を名前に入れて保管するため、出力のたびに入れ替えたい。画面の欄に入れた名前がそのまま `Content-Disposition` に乗る。空欄なら「時間割」。入れた名前は `localStorage` に残す（毎年おなじ付け方をするので、出力のたびに打ち直さずに済む）。

**名前は拒まず、整えて通す。** Windows が使えない文字（`\ / : * ? " < > |`）・制御文字・前後の空白・末尾のドットを落とし、予約名（CON・NUL など）と空文字は既定へ戻す。出力の直前に名前で弾かれると、生成し直しになりかねない。区切り文字を落とすので、上の階層を指す名前にはならない。非 ASCII は Starlette が `filename*=utf-8''` で百分率符号化するため、ヘッダが壊れることもない。

**事務局がこれまで手で作ってきた様式に合わせる。** 見本は「2026時間割（新経営学科）.xlsx」。当初はマトリクス形式（縦 1〜5 限 × 横 月〜金、1 セルに改行で併記）で出していたが、事務局が長年 Excel で管理してきた形とかけ離れており、受け取ってからの手直しが前提になっていた。**紙の形を変えさせるのではなく、こちらが紙に合わせる。**

学科 × 学期で 6 シート（経営・前期／後期、会計・前期／後期、短大・前期／後期）。集中講義は別シートにせず、各シートの右端に「集中」の欄として置く。学科と学期で振り分けるので、どの紙を見てもその区分の全部がそろう。通年の集中講義は前期・後期のどちらにも出す（片方だけだと、もう片方を見た人が見落とす）。

```
行1  経営学科　前期                                    2026.09.28
行2  月曜日：対面 │ 火曜日：対面 │ … │ 金曜日：遠隔 │ 集中
行3  抽選│人数│授業科目名│教員│教室│備考
行4〜 A列=時限（縦結合） B列=年次（縦結合） その下に科目を縦に並べる
```

**教室・抽選・人数は空欄で出す。** カリキュラム一覧にその列が無く、埋める元が無い。見本のシート名が「教室入」であることからも、ここは事務局があとから手で入れる欄である。枠だけ用意して渡す。データが無いところを推測で埋めない。

**同じ科目を複数の教員が持つときは、科目名を 1 回だけ書く。** 課題研究Ⅰは 18 名、卒業研究Ⅰは 16 名が担当する。毎行繰り返すと読めなくなるので、教員を続く行に並べ、科目名と備考のセルを縦に結合する（見本の E5:E8 と同じ形）。

**大学と短大で列が違う。**

| 学科 | 曜日ブロックの列 |
|---|---|
| 経営・会計 | 抽選 │ 人数 │ 授業科目名 │ 教員 │ 教室 │ 備考（必修のみ「必」） |
| 短期大学部 | 抽選 │ 人数 │ 授業科目名 │ 備考（前①など） │ 教員 │ 教室 │ 必修（必・選必） |

短大にはクオーター科目が 47 件あり、大学には 1 件も無い。開講期を書く欄が要るのは短大だけなので、そこだけ科目名の右に「備考」を足し、末尾を「必修」に変えて必・選必を書き分ける。大学は見本どおり、末尾の「備考」に必修の「必」だけを出す（選択必修は空欄）。

**金曜の教室欄は大学にだけ無い。** 大学のカリキュラム一覧は遠隔列が ○ か × で埋まっており空欄が無いため、H8 により金曜へ来るのは遠隔科目だけになる。教室が要らないので見本も落としている。短大は ○ か空欄で × が無く、対面科目が金曜に来うるため残す。

**横の区切りは 3 段階。** 時限のあいだは太い実線、年次のあいだは点線、同じ年次の中には線を引かない。1 科目が教員の人数ぶん行を使うため、1 行ごとに線を引くと科目の切れ目が分からなくなる。**集中の欄は科目が尽きたところで太い実線を引いて終える。** グリッド側は 5 時限 × 年次ぶんの高さが必ず要るが、集中はあるだけしか無い。下まで空の枠を伸ばすと、何も無い場所を延々と目で追うことになる。

**科目名を折り返すのは、縦に結合したセルだけ。** Excel では `wrapText` が `shrinkToFit` を打ち消す。1 行しかないセルで折り返すと 2 行目が行高に隠れて読めなくなるため、そこは縮めて収める。見本も同じ使い分けをしている。

**網掛けは市松に敷く。** 曜日と時限を足して偶数の升目に薄い灰色を置く（1 限は火・木、2 限は月・水・金、以下交互）。横に 5 曜日ぶん並ぶため、目が 1 行ずれると別の曜日を読んでしまう。色は見本で使われていたものと同じ `#DDDDDD`。

**時限の欄には授業時間を添える。** 「1時限／8：50〜10：30」の 2 段。科目が少ない時限でもこの 2 段が隠れないよう、時限のブロックには最低 5 行ぶんの高さを取る（足りないぶんは最後の年次に足す）。

**短大は集中の一覧を表の下へ回す。** 曜日ブロックが 7 列あり（大学は 6 列）、右へさらに継ぎ足すと 1 枚に収まらないほど横長になる。表の下に 1 行あけ、さらに**左を 1 列あけて** B 列から並べる。左端にぴったり寄せると、上の表の時限の列と縦につながって見え、集中が時間割の続きのように読めてしまう。列幅は曜日ブロックのものを結合して使い、B〜I に収める（表の幅いっぱいまで枠を伸ばすと、右側の空の升目が「まだ続き」に見える）。**広げるのは結合しないと入らないものだけ**で、年次・教室・必修は上の表で同じものが入っている列の幅をそのまま使う。どれか 1 つだけ広いと、そこが間延びして見える。

用紙は A3 横、1〜3 行目を各ページに繰り返し、C4 で固定する。**開いたときの表示倍率は 40%** にしておく。A3 横 1 枚ぶんの幅があり、既定の 100% では右端が画面に入らない。**倍率は決め打ちにしない**（見本は 36% 固定だが、科目が増えた年に右端が黙って切れる）。幅に合わせて縮め、縦は必要なだけページを使う。

## 10. 設定と保存先

| 対象 | 保存先 |
|---|---|
| Gemini API キー | `backend/.env` の `GEMINI_API_KEY` |
| モデル名・予備モデル・再試行回数 | `backend/data/settings.json` |
| アップロードした Excel と生成結果 | `backend/data/sessions/<id>/`（`files/` と `result.json`） |
| 生成ログ | `backend/logs/` |
| 異体字・科目個別例外・前後期対応・編成規則 | `backend/config/*.json` |

`.env` は `.gitignore` に登録する。API キーはフロントへ全文を返さない。先頭数文字だけを残してマスクし、短いキーでも末尾が必ず隠れるようにする。

`settings.json` が壊れている場合は既定値へ落とす。設定が読めないだけでシステムが起動しなくなるのは割に合わない。

**保存先のルートは差し替えられる。** 上表の置き場所は `app/paths.py` が一括で決め、既定は `backend/`、環境変数 `TIMETABLE_DATA_DIR` で移せる。別プロセスで起動したサーバを相手にするテスト（§13）が、実運用のセッションとログを踏まないために要る。

## 11. エラー処理

| 事象 | 対応 |
|---|---|
| API キー無効 | ログに記録し、モックモードへの切り替えを促す |
| レート制限・モデル混雑 | 次の予備モデルへ切り替えて再送（§8.6） |
| JSON パース失敗 | 再試行の対象とする |
| タイムアウト | 再試行の対象とする |
| 再試行の上限到達 | Stage 5 のソルバーへフォールバック |
| Excel の列構成が想定外 | MarkItDown 経路にフォールバックし、警告を表示 |
| Excel が読めない | どのファイルが原因か分かる 400 を返す。スタックトレースは返さない |
| 生成が例外で終わった | `status = failed` として返す。**成功として見せない** |

**生成が途中で完全に停止することはない。** どのエラー経路も最終的にソルバーへ到達し、時間割は必ず出力される。

### フロントエンド（DOM スタブ）

画面側を自動検証の外に置くと、バックエンドのテストをいくら足しても見つからない不具合が残る。ただし**ブラウザ全体を用意する必要はない。** `backend/tests/js/dom_stub.js` は `innerHTML` を文字列として持つだけの最小限の DOM で、「何を書き出したか」「どの要素が有効になったか」を確かめるにはこれで足りる。ドライバが結果を JSON で出し、pytest 側が読む。`node` が無い環境では自動的に飛ばす。

| ドライバ | 対象 |
|---|---|
| `restore_session.js` | セッション復元。どのタブが有効になるか |
| `timetable_render.js` | 学年順の並び、複数コマの移動、未配置科目の配置、HTML エスケープ |
| `settings_models.js` | 予備モデルの表示・保存・並び順、ログパネルの開閉 |

テストハーネスを `frontend/` ではなく `backend/tests/` に置いているのは、`make-dist.sh` が `tests` という名前のディレクトリを配布物に見つけるとビルドを中止するためである。

### 実ブラウザ（E2E）

DOM スタブでは fetch の往復・SSE・HTML5 ドラッグ&ドロップ・ダウンロードが検証できない。`backend/tests/e2e/` は uvicorn を別プロセスで起こし、Chromium から「読込 → モック生成 → 結果描画 → コマの移動 → Excel 出力」を 1 本通す。

通す道は 5 本ある。読込から Excel 出力までの 1 本に加え、コマの移動と取り消し、教員別ビュー、保存済みセッションの選び直し、生成の中止。読込からモック生成までは `tests/e2e/helpers.py` に 1 本だけ置いて共有する。

- **モックモードで走らせる。** AI モードは無料枠を消費し数十分かかる。モックなら同じ経路を無料かつ 10 秒ほどで決定的に通せる
- **`live_server` は `TIMETABLE_DATA_DIR` を渡す**（§10）。別プロセスのサーバには `tests/conftest.py` の monkeypatch が届かないため、渡さないと実運用のセッションとログを実行のたびに追い出す
- 遅く Chromium を要するので `pytest.ini` の `addopts = -m "not e2e"` により通常の実行では走らない。`-m e2e` で明示する
- コマの移動は「ドラッグがサーバまで届くこと」を確かめる。落とし先が制約に触れるかはデータ次第なので、空きコマの妥当性に結果を委ねるとテストが日替わりになる。配置の可否そのものは制約のテストが受け持つ
- **取り消しを試すときは、動かせる組み合わせを先に 1 つ探してから掴む。** 実データの時間割はほぼ埋まっており（経営・前期は 25 コマ中 3 つしか空いていない）、適当なカードを適当な空きコマへ落としても大半は制約で断られる。探すのは制約の判定を確かめるためではなく、**掴んで落として取り消せること**だけを見るためである
- **1 コマに 1 枚しか無いカードを選ぶ。** 9 枚が重なるコマもあり、ドラッグの当たり判定は目当てのカードではなく手前の 1 枚を掴む。実際それで別の科目が飛んだ
- **踏襲モードは E2E に足さない。** 前年度の Excel がリポジトリに無く、実データでしか検証しないという方針（§4.5）と両立しない

開発中に画面を直接操作して確かめる手段として、`.mcp.json` に Playwright MCP を登録してある。**バージョンは固定する。** 最新を取りに行く設定にすると、起動のたびに未レビューのコードが走り、要求される Chromium のリビジョンが上がった瞬間に黙って起動失敗する。
